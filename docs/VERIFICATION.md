Проверена локальная ветка `feature/booking-core`. Проверка не означает, что изменения

## Браузерная проверка

Использовалась отдельная временная БД с синтетическими аккаунтами и объявлением.
Рабочая база и реальные пользователи для тестирования не изменялись.

- Телефон: ширины 360 и 390 px; десктопный чат: 1440 px.
- Вход, главная, каталог, карточка жилья, кабинет и редактирование профиля.
- Первый шаг создания объявления: поля и горизонтальная навигация шагов; устранено
  переполнение декоративных изображений. Полный шестишаговый мастер в браузере
  в этот прогон не проходился.
- Админка: статистика из БД, поиск аккаунта, окно подтверждения действия.
- Чат: загрузка, отправка и сохранение сообщения после перезагрузки.
- Фото прямоугольного исходного размера обрезается кругом: 40×40 px в сообщении,
  44×44 px в шапке. Без фото отображаются инициалы; картинка не сжимается во flex.
- Исправлены переполнение шапки, ширина колонок карточки жилья и мобильная рассылка.
- Убраны вымышленные live-показатели кабинета и утверждения об уже выполненной
  проверке личности. Неподключённое сохранение описания профиля явно недоступно.

Это целевая проверка основных сценариев, а не полный проход каждого макетного
экрана и каждого устройства. Реальный iPhone/Safari, Android-устройство, нагрузочное
тестирование, доставку писем, Google OAuth и производственный деплой в этот прогон
не включали. Финансовые операции намеренно остаются демонстрацией.

## Воспроизведение

Запустите отдельный PostgreSQL с правом CREATE DATABASE и задайте
`TEST_POSTGRES_CONNECTION`, затем выполните команды из таблицы. Интеграционные
тесты создают собственные временные базы и удаляют их. Без подключения PostgreSQL
часть проверок пропускается — это не эквивалент полного прогона.

Перед будущим слиянием нужно сверить конфигурацию Docker/deploy с main, применить
миграции на тестовом окружении, передать bootstrap-секреты API и повторить ключевой
сценарий на опубликованном сайте. Конфигурация существующего деплоя не заменялась.
