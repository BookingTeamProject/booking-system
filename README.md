# TrailsUA

Платформа каталога жилья и бронирований: React / TypeScript, ASP.NET Core 10,
EF Core 9, PostgreSQL 16.

## Локальный запуск

Нужны .NET SDK 10, Node.js 22.12+ и Docker с Linux-контейнерами.

1. Запустите БД: `docker compose up -d postgres`.
2. Запустите API: `dotnet run --project backend/TrailsUA.API --launch-profile http`.
   Миграции и начальные категории применяются при запуске. API: `http://localhost:5238`.
3. В каталоге `frontend` выполните `npm ci`, затем `npm run dev`.
   Vite перенаправляет `/api` и `/uploads` на локальный API.

Для отдельной базы задайте `ConnectionStrings__DefaultConnection` в окружении API.
`DB_PASSWORD` переопределяет пароль подключения. JWT на сервере настраивается через
`JwtSettings__SecretKey`, `JwtSettings__Issuer`, `JwtSettings__Audience`.
Вне локальной разработки используйте собственный секрет подписи.

Frontend по умолчанию обращается к `/api` на своём домене. Для другого адреса
скопируйте `frontend/.env.example` в `frontend/.env.local` и измените
`VITE_API_BASE_URL`. Переменные `VITE_*` применяются во время сборки.

## Бронирования

Гость выбирает даты и количество гостей, получает расчёт сервера и отправляет
заявку. Хозяин видит её в «Мои помешкання → Заявки та бронювання» и подтверждает
или отклоняет. Гость видит свои заявки в «Бронювання» и может отменить их до начала
проживания (включая день заезда). Изменения сохраняются в PostgreSQL.

Подробные правила, API и сценарий проверки: [docs/BOOKINGS.md](docs/BOOKINGS.md).

## Централизованные источники данных

Выбор делается в одном месте: `frontend/src/config/dataSources.ts`.
Задайте `VITE_DATA_MODE=live` (по умолчанию) или `VITE_DATA_MODE=demo` в
`frontend/.env.local` и перезапустите Vite / пересоберите сайт.

`AppDataContext` предоставляет один контракт для каталога, категорий,
бронирований, избранного, отзывов и финансов. В live используются HTTP-адаптеры;
в demo — отдельное браузерное хранилище для каждого пользователя. Сброс демоданных
не затрагивает сессию и настройки. Ошибки API не подменяются тестовыми данными.
Авторизация остаётся серверной в обоих режимах.

Реальные платежи и выплаты исключены из объёма диплома. В live финансовые
функции недоступны; в demo можно проверить кошелёк и тестовые операции.

Подробности, контракты и границы миграции: [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md).
Новости и demo-поддержка также используют общий контракт; реальные операторы и
отправка писем не подключены. Часть старых макетных экранов остаётся демонстрационной.

Языки и валюты перечислены в `frontend/src/config/locales.ts`. Все три
переключателя используют этот реестр и общее состояние `SettingsContext`.
Перевод текстов остаётся отдельной задачей: существующий словарь пока неполный.

## Проверки

```powershell
dotnet test backend/TrailsUA.slnx
cd frontend
npm run build
npm run lint
npm test
```

Без `TEST_POSTGRES_CONNECTION` тесты PostgreSQL явно пропускаются. Чтобы проверить
миграции, HTTP-сценарий и конкурентные запросы, задайте подключение к отдельному
локальному PostgreSQL с правом `CREATE DATABASE`:

```powershell
$env:TEST_POSTGRES_CONNECTION='Host=localhost;Port=5432;Database=postgres;Username=postgres;Password=YOUR_LOCAL_PASSWORD'
dotnet test backend/TrailsUA.slnx
```

Тесты создают базы `trailsua_test_<uuid>` и `trailsua_api_test_<uuid>` и удаляют
только их. Workflow `validation.yml` выполняет эти проверки на PostgreSQL 16 и
собирает frontend. ESLint также выполняется в CI и блокирует проверку при ошибках.

Docker-деплой сайта находится в ветке `main`. Изменения текущей ветки не развёртывают
сайт автоматически; перед слиянием необходимо сохранить актуальную конфигурацию
Docker и деплоя из `main`.

## Объём диплома

Материалы для защиты: [стек, архитектура, сценарий выступления и вопросы](docs/DEFENSE_GUIDE.md).
[Передзащита: презентация для двух программистов и порядок подготовки](docs/PREDEFENSE.md).
Инструкция по созданию главного администратора и матрица прав: [ADMIN.md](docs/ADMIN.md).
Результаты и границы проверки: [VERIFICATION.md](docs/VERIFICATION.md).

Реальные платежи, сохранение банковских карт и выплаты не реализуются.
Финансовый модуль демонстрирует архитектуру и сценарии на тестовых данных.
В рабочем режиме бронирование выполняется без онлайн-оплаты.

Переписка доступна только участникам бронирования. ID диалога совпадает с ID
бронирования; прежние общие демодиалоги `c1` недоступны через API. Обновление
сообщений выполняется кнопкой; вложения и realtime-доставка пока не реализованы.
